# Changelog

## 2.0.1 -- 2026-11-15

A patch release. The Technical Standard and the Overview are unchanged (2.0.0); the reference implementation and the Validation Report are updated.

**Reference implementation**
- `evaluate_statuses()` now enforces the Standard's rule that a status computed against a Review line other than the normative 0.80 is not an MRFS status (Technical Standard, Section 2.6). Such statuses are still computed but flagged: the result carries `mrfs_status: False` and a note. Results with the default 0.80 line are unchanged.
- New test for this rule; `test_metrics.py` now has 22 tests.

**Validation Report (2.0.1)**
- States the number of bootstrap resamples: 500 in Sections 4 to 8 (`N_BOOT` in `run_validation.py`) and 400 in Section 9; the implementation default is 1,000. No figure changed.
- Test count and description updated to 22 tests.

## 2.0.0 -- 2026-10-11

A major version: the exposure metric E1 is redefined and its values are not comparable with v1.0 and v1.1.

**Documents**
- The six volumes and the Validation Report are consolidated into three documents: the MRFS Overview, the MRFS Technical Standard (one integrated normative document, with the worked example, the changes from v1.x, the reference-implementation mapping and the design-choice sources as appendices) and the MRFS Validation Report. They are typeset from `docs/publication/` with pandoc and XeLaTeX (`make_publication_docs.py`, `build_publication.py`), with a contents list, bookmarks, numbered tables and figures, and typeset formulas. The methodology is unchanged by the consolidation.
- `tools/make_release.py` assembles the curated release folder from an explicit file list.
- All content rewritten to the revised design. The governance chapter is a reference charter for adopting organisations. MRFS does not approve or block releases; Review Required calls for a documented investigation and a decision by the adopting organisation.
- New: the MRFS Validation Report, generated from `src/validation_results/`, replacing the separate validation addenda of v1.x.
- README, ARCHITECTURE and CITATION rewritten for the new version; the citation metadata declares both licences. One consolidated bibliography (`docs/References.md`).
- The worked example (Technical Standard, Appendix A) is generated by the reference implementation from a seeded synthetic marketplace.
- Fixed minimum event counts, universal data-quality thresholds, alert colours and the undefined "sustained for more than two weeks" drift rule are withdrawn. 0.80 is stated as an MRFS choice by analogy to the four-fifths rule; 0.85 and the drift lines are MRFS defaults that can be changed if pre-specified.

**Breaking: the exposure metric E1 is redefined**
- v1 divided a cohort's share of top-K positions by its share of *sellers*. A cohort with a quarter of the sellers and a few percent of the listings then scored far below 1 under a ranker that ignores cohort. E1 now divides the top-K positions a cohort holds by the number expected from its share of *listings in a declared comparison population*, event by event. E1 values from v1.0 and v1.1 are not comparable with the new values.
- Every result now depends on a declared comparison population: the candidate set at a named stage (platform audit) or the results retrieved to a stated depth (external assessment). Statuses are assigned only for a candidate population and apply to the declared stage only.

**Reference implementation**
- `src/metrics.py` rewritten (version 2): E1 as above; E2 as event-weighted normalised mean rank; E3 as a Gini index that includes sellers with no top-K position; O3 as one ratio per outcome; S1 defined against the mean of the preceding baseline windows; S2 added as the ratio of E1 between two ranking versions with an interval. All intervals resample whole ranking events and recompute numerator and denominator. Thresholds are parameters of an audit declaration, with the MRFS defaults (0.80, 0.85; drift 10% and 20%).
- A cohort labelled in the seller records but with no listings in the comparison population is now reported by E1 with zero expected positions, an undefined ratio, no interval and the status Not Evaluated (previously omitted, or Insufficient Data when its only listings were in excluded events). Default size cohorts are tested under heavy ties; when the two quartile values coincide the default split is refused rather than overlapping.
- No interval is formed when a numerator count is zero (all resamples would be zero); the result is Insufficient Data. E2 accepts a declared ordered depth. The audit declaration records windows, resampling unit and strata.
- New: `src/generate_synthetic_audit.py` (deterministic synthetic marketplace, sized in ranking events), `src/test_metrics.py` (21 tests with hand-worked expected values), `src/run_validation.py` (synthetic validation), `src/generate_sample_audit_report.py` (sample audit report produced entirely from code).

**Corrections**
- The synthetic validation published with v1.0 and v1.1 counted log rows as ranking events (20 rows per event). Its results were therefore obtained at one twentieth of the stated scales. `src/validation_results/` holds the replacement, in ranking events.
- The description of Ursu (2018) now matches the paper, which found that rankings affect what consumers search but, conditional on search, not purchases.

**Other changes since 1.1.0**

- References corrected. The TREC 2021 Fair Ranking Track overview (arXiv:2302.10856) is by Ekstrand, McDonald, Raj and Johnson; v1.x listed the organisers of an earlier year's track. The DOI for Sapiezynski et al. (2019) is now 10.1145/3308560.3317595.
